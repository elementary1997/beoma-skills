# ADR 0001: Переносимые скиллы и явная установка

Статус: принято для MVP, 2026-10-10.

## Контекст
Четыре агента поддерживают SKILL.md, но пути загрузки и доставка в удалённые среды различаются. Репозитории независимы. Универсального GitHub-параметра, автоматически подключающего каталог к каждой сессии, не установлено.

## Решение
Канон — `skills/`, установка копий Python-скриптом; хеши защищают локальные изменения. В проектах фиксировать Git SHA источника и запускать bootstrap до сессии. Глобальный режим удобен для одной машины. Не скачивать latest скрыто внутри каждой сессии.

## Последствия
Нужен явный шаг onboarding/setup. Обновления требуют повторной установки. Проектные копии можно коммитить, чтобы облако видело их без доступа к приватному источнику. Одинаковый формат не гарантирует одинаковое качество выполнения.

## Альтернативы
Symlink на общий checkout — проще обновлять, но непереносим в отдельные worktree/облако. Submodule — фиксирует версию, но требует инициализации и сам не регистрирует скиллы. Marketplace/plugin — полезен позже для специфичных возможностей, добавляет разные механизмы доставки.
